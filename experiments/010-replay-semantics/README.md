# E010 — Replay semantics

**Status:** run 2026-10-07, offline (scripted model). Results below. **Re-run 2026-10-07 after the provider-neutral refactor (journal schema v2, `ScriptedBackend`, `ModelError`): the same 9 outcomes.** R1 now prints 66 trace lines (the demo script gained a malformed call); R5/R6 use neutral `transient`/`permanent` errors instead of HTTP 429/400. `results/e010-results.md` holds the v2 table.

## Question

What exactly can we reproduce from an append-only execution journal?

## Hypothesis (written before running `run_e010.py`)

1. *Inspection*: the full transcript the model saw, and a readable timeline, can be rebuilt from events and blobs alone, without the task files.
2. *Deterministic re-execution* of an unchanged kernel against the recording will match every event except volatile fields (timestamps, durations, ids, request ids).
3. Replay will **detect** kernel changes, and the first divergence will point at the right place:
   - a changed policy → a `permission_checked` event differs;
   - a changed tool description → request 1 differs (the tool list is part of every request);
   - a changed tool implementation → a `tool_completed` event differs.
4. Changes *outside* the recording (fixture files edited on disk after the run, the task file edited) will **not** affect replay, because the recording carries its own copy of the task config and starting files.
5. Transient API errors (retries) cannot be replayed, but skipping them still lets the rest match.
6. A run that died on a permanent API error can only be replayed up to that error.
7. Model re-execution (asking the real model again) cannot be done offline at all and is not replay.

## Interpretation (Inferred)

From an append-only journal we can reproduce three different things, and they must not be confused:

1. **Inspection** (always possible): what the model was shown and what it answered, every tool call, every decision. This needs only the journal, not the task files.
2. **Deterministic re-execution of the kernel** (possible for every run that did not end in a permanent API error): with recorded model responses, recorded human decisions and the recorded starting files, the current kernel reproduces the recorded run exactly, or tells us the first event where it no longer does. This is a regression test for *our code*, not a statement about the model.
3. **Model behaviour** cannot be reproduced at all. A recorded response is a single sample. Asking again (`agent-lab rerun`) is a new experiment run.

The event-level comparison catches divergence earlier than the request-level comparison (R3a: event 5 vs request 4). The request check matters for a different reason: if a request differs, the recorded response no longer answers the question being asked, so replay must stop there.

"Determinism" here holds because Phase 1 tools are pure file operations on a recorded snapshot. It is a property we checked, not a guarantee of the design.

## Uncertainty (Not yet verified)

- All cases use a scripted model. A recording of a real Opus 5.5 run contains thinking blocks with opaque signatures; replay serves them back unchanged and never sends them to the API, so they should not matter. Not verified until a live run is recorded (needs an API key).
- Replay re-runs the tools for real. Phase 1 tools are deterministic file operations; future tools (time, network, randomness) will not be, and will need recorded results instead.

## New Questions

- When we have a live recording: do Opus 5.5 thinking blocks (opaque signatures) survive replay untouched, and does `rerun` produce the same tool sequence on a simple task? How often?
- Should replay continue past the first divergence and report a full diff instead of stopping (useful for forks)?
- Tools that read time, randomness or the network will break re-execution. Record their outputs as events and serve them in replay (as we do for the model)? That is the step towards forking.
- Is "MATCH" too strict for harmless kernel changes (e.g. adding a field to an event payload)? Do we need event schema versions before Phase 2?
